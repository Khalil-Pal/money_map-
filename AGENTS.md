Guidance for AI coding agents (Codex, ChatGPT) working in this repo.

## What this is

**Jeib · جيب** is a local-first Windows desktop app to plan, track, and review personal spending.
It is the single portfolio project of Khalil, a student aiming to become a Junior Backend Developer
(Java) / System Analyst by end of March 2027. Repo: https://github.com/Khalil-Pal/money_map-

Because it is a learning + portfolio project, **how Khalil works matters as much as the code**.
See "Working agreement" below. Read it before writing anything.

## Stack

- Java 21, JavaFX 21 (FXML + CSS), MVVM-style layering
- SQLite + Flyway (plain JDBC repositories, no ORM)
- JUnit 5, Mockito
- Packaging: jlink + jpackage, distributed as a zip via GitHub Releases
- Later (Phase 3, not now): Spring Boot 3 sync backend, PostgreSQL, Redis, RabbitMQ
- Out of scope, recommend against: microservices, Kubernetes, GraphQL, web frontend, mobile app

## Commands

Use JDK 21 (`JAVA_HOME`). Use the Maven wrapper (`mvnw.cmd` on Windows).
An old Java 8 shim is first on PATH, so a bare `java -version` shows 1.8; Maven uses `JAVA_HOME`, so builds are fine.

```bash
./mvnw javafx:run                      # run the app
./mvnw test                            # all tests
./mvnw test -Dtest=LimitRulesTest      # one test class
./mvnw package                         # jar + target/libs
powershell -ExecutionPolicy Bypass -File scripts/package-windows.ps1   # dist\Jeib\Jeib.exe + zip
```

## Code layout

- `com.jeib.Launcher` is the entry point (needed so JavaFX runs from the classpath); `JeibApp` wires everything.
  `JeibApp.createMainWindow(database, clock)` is the one place the app is wired.
- `model/` records and pure rules (`LimitRules`, `Money`, `LeftPerDay`), `db/` (`Database`),
  `repository/` (plain JDBC), `service/` (rules, validation, commands, undo), `ui/` (FXML + controller + view-model per screen),
  `i18n/` (`Messages`, `Arabic`).
- MVVM: controllers only bind FXML to a view-model. View-models hold state as JavaFX properties and keep
  DB work in plain methods so tests run without JavaFX.
- The DB lives in `%APPDATA%\Jeib\jeib.db`; tests use `@TempDir`.
- Schema changes: add a new `V<n>__name.sql` under `src/main/resources/db/migration`. **Never edit an applied migration.**

## Non-negotiable engineering rules

- **Money is never `double`.** Integer minor units (cents) in the DB; `long` or `BigDecimal` in Java.
  Exchange rates are `BigDecimal` (max 6 decimals). Convert sums per currency, then convert once
  (`ExchangeRates.toMain`, half-even rounding).
- **IDs are UUID text, generated by the client.** No auto-increment on synced tables.
- **Every synced table has** `created_at`, `updated_at` (ISO-8601 UTC), `deleted` (soft delete 0/1), `version`.
  Never hard-delete synced rows.
- **Never block the JavaFX UI thread.** DB/file/network work goes in a `Task`; UI updates via `Platform.runLater`.
- **Local-first:** writes go to SQLite first; the UI never waits on the network.
- **Schema changes only through Flyway migrations.** No ad-hoc DDL.
- **Limit status:** `percent = spent / limit * 100` (rounded down); `>= 100` EXCEEDED, `>= 80` WARNING, else OK.
  `spent` = sum of non-deleted EXPENSE transactions in that category and month. Budget with `category_id NULL` = overall limit.
  Test the edges: exactly 80%, exactly 100%, month boundaries, no limit set.
- **Undo/redo goes through the service layer as commands** (`TransactionCommands`, `UndoManager`).
  The UI never calls `TransactionService` directly for add/edit/delete. Undoing a delete restores the
  soft-deleted row and bumps `version`/`updated_at`.
- **"Left per day"** = (overall limit − spent this month) ÷ days left including today. Limit only. No overall limit → the card asks the user to set one.
- Currencies: USD, ILS, RUB only (all 2 decimals). A transaction in a non-main currency needs its rate set first.

## Languages: English, Arabic, and Russian (every user-facing string)

- All user-facing text goes through `Messages.t("English text", args…)`. The English sentence is the key; `{0}`, `{1}` are replaced literally.
  In FXML write `text="%English text"`.
- Add Arabic and Russian translations in `i18n/Arabic.java` and `i18n/Russian.java`. Translation coverage tests fail if one is missing.
- The saved language takes priority over the system display language. Unsupported system languages fall back to English.
- Arabic is right-to-left (`NodeOrientation.RIGHT_TO_LEFT` on the window root). Amounts and other LTR snippets go through `Messages.ltr`
  (`SupportedCurrency.format` already does; use `formatPlain` + `ltr` when adding a sign).
- Arabic-Indic digits are accepted wherever amounts are parsed (`model/Digits`). Displayed numbers stay Western.
- Sidebar items use `userData` as the fixed page id, never their text.

## Design and UI rules

- `jeib-color-system.md` is the source of truth for colors, typography, shape. **Never hard-code hex values**; use its tokens.
- Brand orange `#FF751F` is an accent only (~10% of the screen). Text on orange buttons is dark (`on-primary`), not white.
- `styles/theme-light.css` / `theme-dark.css` hold only color tokens; `styles/app.css` styles components using them.
- Hover highlights only on things that are clickable. Dashboard cards, limit rows, and legend rows are clickable drill-downs into filtered Transactions.
- A bigger design overhaul is planned after Dec 1. Until then keep colors, sizes, and radii in CSS tokens and screens simple,
  so the redesign is mostly CSS and layout.

## Current status (update this after each session)

- All Dec 1 scope is built: categories, transactions, quick-add, undo/redo, limits, dashboard,
  currencies, backups + crash log, settings, localization, and packaging.
- The first Windows build was published as GitHub release `v0.1.0`.
- Calendar has Month, Week, and Year views, a mini calendar, and a list of today's operations.
  The day grid shows transactions and the start and end dates of named budget plans. Choose a day
  to see notes and edit transactions. The day's list groups by category and puts the two built-in
  fallback categories last. Transactions has an inclusive date filter.
- Transactions, categories, and saved monthly limits open their editors from pencil buttons.
  Feedback & Support opens a Gmail draft in the browser.
- Budget plans require a name and have their own dates, currency, limit, and expense categories.
  The first-run setup requires a first named plan, and the plan form can create expense categories.
  Each expense can be assigned to one plan. The plan selection is shared by Budgets and Dashboard.
  Existing monthly limits remain available.
- Light and dark themes switch with an eased crossfade. The Settings gear turns briefly on click.
- Settings has a Danger zone to clear transactions, optionally after saving a PDF with transactions
  and planning data. The reset uses soft deletion and clears session undo/redo. Plans, settings,
  and existing backups stay available.
- Recurring supports monthly bill schedules and next due dates. Goals supports savings targets
  and manual contributions. Confirming bills as paid and reminders are future work.
- Reports exports completed named plans to Excel or PDF, starting the day after the plan's
  inclusive end date. Both formats include budget and category charts plus the linked transactions.
- The Accounts placeholder is hidden while the feature is deferred. A video guide is future work.
- `Jeib.exe` app image is built by `scripts/package-windows.ps1` (76 MB; zip 59 MB). Not code-signed (SmartScreen warns once).
- Known gaps: Inter font not bundled (falls back to Segoe UI); no real installer (needs WiX); Java 8 shim on PATH.
